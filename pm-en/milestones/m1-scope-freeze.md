# Milestone 1: scope freeze

**Friday 16 October.** From this day the v1.1 scope does not change without a decision from @maren that is written into the [release plan](../release-plan.md). A new idea goes on the backlog for v1.2.

## Exit criteria

- The scope table in the release plan is agreed by every owner.
- Every item in scope has a spec note that says when it is done: Notifications and Pickup flow.
- Each item has an owner and a date in the work package notes.
- The things left out are named, so nobody expects them: barcode scanning and returns.

## What happened

Met on the day. Barcode scanning came back as a request from two shops during the week and was declined with the same reason as before: it would add a week of testing to a release that needs the message and the code first. [SMS first](../decisions/sms-first.md) was decided two days earlier, so the scope table could name the channel.
