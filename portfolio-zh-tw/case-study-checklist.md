# 案例檢查表

這份是給自己看的，不放上網站。一篇案例要從「修飾中」改成「可發布」之前，我都先拿它對一遍。內容來自我讀過的作品集建議（例如 Nielsen Norman Group 對設計作品集的指引，以及招募主管的說法），也來自已經寫好的三篇。

## 動筆之前

- [ ] **整個案子用一句話講完，而且裡面有結果。** 「三張讓社區禮堂坐滿人的海報。」如果寫不出來，這個案子還不適合寫成案例。
- [ ] **三到五篇案例就好。** 寧可少而深。第四篇只有在它展示了前面幾篇沒有的東西時，才值得加。
- [ ] **確認我能公開什麼。** 客戶同意、保密協議，還有圖片裡有沒有私人資訊。

## 每篇案例都要有的四個部分

1. **問題。** 當時的情況是什麼、為什麼重要？寫出人名和地名，不要只寫「客戶」。
2. **我的角色。** 我做了什麼，以及同樣重要的，我沒做什麼。讓審閱的人猜，就會失去信任。
3. **過程。** 寫決定，不要寫活動。不是「我做了訪查」，而是訪查發現了什麼、我因此改了什麼。
4. **成果。** 有數字就放數字；沒有的話，寫什麼改變了、客戶怎麼說。每個數字都要交代出處。

## 讓它變好的細節

- [ ] **標題寫出發現。** 「先畫九張小稿，才挑出一張」比「發想」更有內容。
- [ ] **寫我捨棄了什麼，為什麼。** 招募主管明白地說過，他們想知道設計裡「沒有」什麼。
- [ ] **每個主張旁邊都有圖。** 圖放在需要它的那句話旁邊，就能替一整段文字做事。
- [ ] **圖說寫「該看哪裡」**，而不是「這是什麼圖」。
- [ ] **大約九十秒能讀完。** 快速瀏覽時，仍然找得到問題、角色和成果。

## 寫完之後

- [ ] 用陌生人的眼光讀第一個畫面。看得出這是什麼案子、我做了什麼、為什麼值得在意嗎？
- [ ] 出聲唸過一遍，把我不會這樣說的句子都刪掉。
- [ ] 把狀態改成「可發布」，再收進網站的書裡。
